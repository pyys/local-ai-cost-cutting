# reference - 오케스트레이션 참조 구현

[No.4 오케스트레이션](../docs/ko/04-orchestration.md)이 설명하는 패턴을 **한 파일로 읽을 수 있게** 모은 것이다.

```
orchestrator.py    인코더 1벌 + 디퓨전 워커 N벌
```

---

## 왜 패치가 아니라 참조 구현인가

인코더와 워커를 띄우고 작업을 분배하는 코드는 **프로젝트마다 구조가 다르다.** 웹 서버 프레임워크, 작업 큐, 상태 저장소, 인증이 각자 다르게 붙어 있어서, 특정 프로젝트에 대한 diff 를 배포해 봐야 다른 사람에게는 적용할 수 없다.

그래서 **패턴만 남기고 프로젝트 고유 부분을 전부 걷어냈다.** 그대로 실행하기보다 자기 코드에 옮겨 심는 용도다.

`patches/` 쪽은 반대다. [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp) 라는 **공개된 단일 대상**이 있으므로 실행 가능한 패치로 배포한다.

## 담긴 것 넷

### 1. GPU 는 UUID 로 지정한다

인덱스는 장비 수가 바뀌면 밀린다. 이 프로젝트에서 인코더 카드를 꽂았을 때 LLM 용 카드가 index 1 에서 2 로 밀렸다. 인덱스로 지정했다면 16GB 카드에 30GB 모델이 올라가려다 OOM 이 났을 것이다.

```python
env["CUDA_VISIBLE_DEVICES"] = gpu_uuid
```

**"메인 GPU 지정" 옵션만 믿으면 안 된다.** 보조 모듈이 다른 카드에 얹혀 나중에 OOM 을 낸다. 카드 하나만 보이게 만든 뒤 인덱스 0 을 쓰는 것이 확실하다.

### 2. 워커 수를 상수로 가정하지 않는다

```python
WORKER_PORTS = [8081, 8082]          # 워커 수는 이 목록의 길이로만 결정된다
port = WORKER_PORTS[i % len(WORKER_PORTS)]
```

카드를 늘릴 때 `GPU_UUIDS` 와 `WORKER_PORTS` 에 항목만 추가하면 된다. **워커가 동질하다고도 가정하지 않는다** - 성능/VRAM/아키텍처가 다를 수 있다.

### 3. 기동은 직렬화하고 종료에는 kill 폴백을 둔다

이 프로젝트에서 **가장 많은 시간을 잃은 지점**이다.

```python
_start_lock = threading.Lock()       # 로딩 20초 사이의 중복 기동을 막는다
```

```python
proc.terminate()
proc.wait(timeout=10)
except:  proc.kill()                 # 로딩 중에는 SIGTERM 이 늦게 처리된다
```

둘이 없으면 **포트당 프로세스가 2개씩** 남아 CPU 와 디스크를 두고 싸운다. 실제로 인코딩이 14초에서 56초로 늘었다 -> [함정 모음](../docs/ko/99-pitfalls.md#4-프로세스-관리)

### 4. 1장 = 1작업으로 쪼갠다

```python
for i in range(count):
    port = WORKER_PORTS[i % len(WORKER_PORTS)]
    ... _post(port, "/sdcpp/v1/img_gen", {"conditioning_path": cond_path, "batch_count": 1, ...})
```

프롬프트 대신 **조건 텐서 경로**를 넘기므로 인코딩은 앞에서 1회면 된다. 이렇게 쪼개면 둘을 동시에 얻는다.

- **완성되는 대로 1장씩 내보낼 수 있다** -> [No.3 조기 표시](../docs/ko/03-pipeline-throughput.md)
- **워커 간 불균형이 최대 1작업으로 제한된다** - 정적 라운드로빈으로 충분하고 동적 디스패처가 필요 없다

쪼개기의 대가는 실측상 **장당 0.03초로 사실상 0**이다 -> [부록 8장](../docs/ko/98-benchmark.md#8-해석---작업을-쪼개는-비용)

## 옮겨 심을 때 주의할 것

**포트가 열렸다고 기동이 끝난 게 아니다.** `sd-server` 는 가중치를 lazy 로드하므로 `listening` 로그가 먼저 나오고 첫 요청에서 모델을 읽는다. 벤치마크 타이머를 서비스 기동 시점에 걸면 모델 로딩이 빠진 값이 나온다.

**`--lora-model-dir` 를 반드시 명시한다.** 기본값이 `.` 이라 서버를 `/` 에서 띄우면 요청마다 루트 전체를 재귀 스캔하다가 심볼릭 링크에서 크래시한다.

**조건 파일을 청소해야 한다.** 512토큰 기준 1개당 약 8MB 이고, `/dev/shm` 에 쌓이면 tmpfs 가 찬다.

**`ENCODER_ON_CPU = True` 로 먼저 검증할 수 있다.** 추가 하드웨어 없이 분리 구조가 작동하는지 확인한 뒤 카드를 사는 순서를 권한다. 인코딩은 크게 느려지지만 **장당 생성 시간에는 영향이 없다** -> [부록 7장](../docs/ko/98-benchmark.md#7-해석---인코더-위치가-미치는-영향)
